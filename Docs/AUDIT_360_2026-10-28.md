# Auditoría 360 — Omnis: El Último Ciclo
**Fecha:** 2026-10-28  
**Alcance:** repositorio GitHub `jhonbaza403/omnis-game`, rama base `main`.  
**Método:** lectura del árbol Git, manifiestos, CI y pruebas visibles. No se ejecutó Unreal Editor, Unity Editor, compilación nativa ni lanzamiento del juego en esta auditoría remota.

## Resumen ejecutivo

**El repositorio NO está vacío.** En el árbol de `main` se observan 704 entradas (497 archivos y 207 directorios), aproximadamente 493.642 bytes de contenido de archivos versionados según el árbol consultado. Contiene una base de Unreal Engine, un proyecto Unity separado, scripts de automatización, pruebas, documentación y un runtime auxiliar Cloudflare.

La prioridad no es crear un videojuego desde cero ni reemplazar el trabajo existente: es reducir la ambigüedad de arquitectura, automatizar validaciones en GitHub y verificar los motores con sus herramientas reales antes de afirmar que compilan.

## Controles automatizados que sí se pueden realizar en GitHub

El workflow añadido en esta rama valida:
1. pruebas Python ya existentes;
2. presencia y coherencia básica del proyecto Unity;
3. parseo de JSON versionados seleccionados;
4. integridad estructural de archivos clave.

No instala Unreal Engine ni Unity, no consume licencias y no publica despliegues. Si falla una prueba existente, se debe corregir el fallo real y no desactivar el control.

## Bloqueadores para cerrar la auditoría

- **B1 — Compilación Unreal:** ejecutar build/automation con Unreal Engine 5.8 real.
- **B2 — Runner:** confirmar contacto reciente del runner y resultado del job; un servicio local activo no prueba que GitLab acepte trabajos.
- **B3 — Gameplay:** comprobar movimiento, cámara, combate, interacción, Nexo, progresión, guardado/carga y derrota/respawn en una ejecución real.
- **B4 — Arte:** inventariar assets reales, licencias, tamaños y referencias rotas; las carpetas de destino no equivalen a contenido terminado.
- **B5 — Seguridad:** escaneo de secretos/dependencias y revisión de permisos de repositorio y workflows.
- **B6 — Release:** producir un build reproducible, registrar versión/commit, artefacto y resultado de lanzamiento.

## Criterio de aceptación

La auditoría se considerará cerrada solo cuando haya: motor maestro declarado; CI verde; compilación real del motor elegido; pruebas de gameplay ejecutadas; build Linux que arranque; revisión de secretos y dependencias; y una release vinculada al commit exacto. Hasta entonces, el estado correcto es **base de desarrollo existente; finalización y compilación real pendientes de evidencia**.

## Actualización de estado — 2026-10-28

### Decisión de motor

La decisión del usuario es **Unreal Engine como motor principal**. `Omnis.uproject` declara `EngineAssociation: 5.8`; esa es la referencia que debe validarse con una instalación real del editor. Unity `6000.3.0f1` queda como proyecto secundario conservado, sin nuevas funcionalidades duplicadas. No se declara Unreal 7 como versión compilable sin evidencia oficial y de CI.

### CI de GitLab comprobada

La última pipeline consultada de `main` es [pipeline 2928901819](https://gitlab.com/omnis-game/omnis-game/-/pipelines/2928901819), estado `failed`. El job `unity_project_validate` terminó con `stuck_pending_no_matching_runners`, no con un error de compilación del juego. El job reportó la etiqueta `omnis-linux-docker` y no tenía runner asociado. Esto significa que el primer bloqueo es la asignación/activación del runner; todavía no hay evidencia de que Unity haya importado o compilado el proyecto en CI.

- Corrección aplicada en la rama de auditoría: se quitó el placeholder vacío y se añadió `UnityProject/Assets/Omnis/README.md` para documentar el propósito de la carpeta y los controles de procedencia/licencias de assets.
- Validación completa posterior: [run 40761974114](https://github.com/jhonbaza403/omnis-game/actions/runs/40761974114) terminó con **conclusión success**. En ese commit pasaron las pruebas Python (24 tests), la validación de estructura Unity, el parseo de JSON versionados y la sintaxis de scripts de shell.

### Alcance de ese éxito

El éxito confirma solo las comprobaciones estáticas definidas en GitHub Actions. No equivale a abrir Unity Editor, compilar scripts dentro del motor, ejecutar PlayMode, generar un build Linux ni lanzar el juego. Esas pruebas siguen pendientes.

### Decisión arquitectónica actualizada — 2026-10-28

Unity se conserva intacto como proyecto secundario; no se implementarán nuevas funcionalidades duplicadas allí. No se elimina contenido de ninguno de los dos motores.
