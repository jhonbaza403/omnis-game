# OMNIS — Emergent systems contract

## Authority and player freedom
The authoritative game server owns persistent state: NPC memory, needs, relationships, faction standing, inventory, wallet balances, market stock, route disruptions, mission state and world changes. Clients request interactions; they do not authoritatively mutate these systems. Deterministic rules decide legality and consequences.

The optional language model is a presentation layer only. It may produce dialogue text. It cannot call tools, execute functions, set prices, grant items, move actors, complete missions or alter relationships. If unavailable or invalid, deterministic simulation continues without generated dialogue.

## NPC memory and LLM bridge
UOmnisCharacterStateComponent remains the source of truth: bounded, replicated and saveable memories, relationships and needs. UOmnisNPCDialogueSubsystem reads at most 12 recent memory entries and sends them from the authoritative server to an OpenAI-compatible chat-completions endpoint.

Trusted server environment:
- OMNIS_LLM_ENDPOINT: HTTPS endpoint for the compatible provider.
- OMNIS_LLM_API_KEY: secret; never commit it or expose it to clients.
- OMNIS_LLM_MODEL: provider model identifier.

Input, output, concurrent requests and timeout are bounded. No gameplay tools or command schema are sent. Model claims do not become memories; the server records only that generated dialogue occurred.

## Existing deterministic foundations
- NPC population manager schedules bounded life simulation and throttles navigation by distance.
- NPC state simulates hunger, energy and social needs and persists memory and relationships.
- UOmnisEconomySubsystem is server-authoritative, uses integer minor currency units, stock/demand price indices, route supply shocks, trade receipts and barter. UOmnisEconomySimulationSubsystem advances bounded daily production and consumption on the authoritative world clock.
- Terrain surface response feeds vehicle grip and deformation.
- Route, market and faction catalogs define the Caracas–La Guaira–Barlovento vertical slice.

## Autonomous regional economy
UOmnisEconomySimulationSubsystem advances the seeded Caracas, Guarenas-Guatire, Caucagua, Río Chico, Higuerote and La Guaira flows from elapsed in-game days. Production and NPC/population consumption change market stock; the existing stock/demand pricing formula then changes quotes. Catch-up is capped at seven game days per tick, clients never simulate authoritative stock, and missing markets are ignored rather than silently created. These rates are fictional balancing units, not real economic statistics.

## Emergent loop
1. A player action changes validated server state (trade, helping an NPC, repairing a vehicle, completing a mission or disrupting a route).
2. Deterministic simulation updates stock, demand, survival needs, reputation and memories.
3. NPC schedules and perception determine who can observe or react.
4. The LLM verbalizes only the NPC's known context; it cannot decide or apply consequences.
5. Persisted consequences can inform later deterministic interactions.

## Geographic truth
The Venezuela triangle JSON contains relative Unreal-unit anchors and conceptual altitude profiles, not surveyed latitude/longitude or a digital elevation model. A defensible Landscape requires licensed/source DEM data, a documented coordinate reference system, coastline/hydrography/road vectors, vertical datum, resampling and a reproducible import manifest. Synthetic interpolation must never be labelled real Caracas topography.

The UE materializer must create and save a World Partition map, Landscape, collision, road and river splines, bridges/tunnels, biome layers, HLODs, navigation data and representative interiors. Generated assets must be checked in or reproducibly generated by the UE 5.8 editor script. Git LFS source meshes must be hydrated before import.

## Vehicle physics gate
The generic pawn that applies force and torque to one simulated mesh is not a production vehicle rig. Land vehicles require Chaos Vehicles wheel setup, suspension, steering, drivetrain, braking, tire/friction tuning and collision assets. Boats require a supported buoyancy model with multiple hull points, drag and water-body integration. Each archetype must pass UE 5.8 PIE, dedicated-server and packaged-build tests on road, slope, mud and water.

## Native certification gate
Green Python/catalog CI is not native Unreal certification. Release remains blocked until UE 5.8 UHT/UBT Editor, Game and Server builds; editor automation for NPC memory, LLM timeout/fallback, economy atomicity, route shocks, save/restore, streaming and vehicle physics; actual map/asset materialization; target-platform cook/package; and a dedicated server plus two-client smoke test are recorded. Attach logs, test reports, package checksums and a manifest tied to the exact commit SHA.

Until then, source implementation and static CI must not be described as a playable or certified release.
