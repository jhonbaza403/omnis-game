# Omnis Linux Docker runner (GitLab CI)

The shared GitLab-hosted runner quota was exhausted when pipeline 337 ran. This project uses a tagged project runner to execute CI jobs on an owner-controlled Linux Docker daemon rather than repeatedly retrying on shared runners.

## 1. Create the project runner in GitLab

Open **Settings → CI/CD → Runners** in this project:

https://gitlab.com/omnis-game/omnis-game/-/settings/ci_cd#js-runners-settings

Create one project runner with:
- Description: `omnis-linux-docker`
- Tag: `omnis-linux-docker` (must match exactly)
- Run untagged jobs: **off**
- Protected: **on** (the default branch `main` is protected; the repository is public)

Copy the runner authentication token that begins with `glrt-`. Treat it as a secret; do not commit it or paste it into an issue/chat.

## 2. Run the runner using Docker Desktop on Windows

Requirements: Docker Desktop using its **Linux container / WSL 2** backend. Keep Docker Desktop and the computer running while jobs execute. In PowerShell, check:

```powershell
docker info --format '{{.OSType}}'
```

The result must be `linux`. Then create persistent runner configuration and start the runner container:

```powershell
docker volume create gitlab-runner-config
docker run -d --name gitlab-runner --restart unless-stopped `
  -v gitlab-runner-config:/etc/gitlab-runner `
  -v /var/run/docker.sock:/var/run/docker.sock `
  gitlab/gitlab-runner:alpine
docker exec -it gitlab-runner gitlab-runner register
```

At the interactive prompts, enter:
- GitLab instance URL: `https://gitlab.com/`
- Runner authentication token: the `glrt-` token from Step 1
- Executor: `docker`
- Default Docker image: `node:24-alpine`

The tag and protected status are managed in the project's runner settings. The Docker socket is mounted so the runner can create the job containers, including the Unity editor image.

Verify the runner shows **online** in GitLab's Settings → CI/CD → Runners. Since it is protected, use it only for trusted protected-branch pipelines.

## 3. Add the Unity license to GitLab CI/CD

Open **Settings → CI/CD → Variables**:

https://gitlab.com/omnis-game/omnis-game/-/settings/ci_cd#js-cicd-variables-settings

Create a variable:
- Key: `UNITY_LICENSE`
- Type: **File**
- Value: the Unity license file (`.ulf`) content obtained from the licensed Unity Editor / Unity licensing workflow
- Protected: **on** (because `main` is protected)
- Do not save the license in Git, Git LFS, artifacts, logs, or this README.

This variable is required by `unity_build_linux`. If the image cannot activate against that license, the job must be treated as failed and its logs reviewed; do not bypass licensing.

## 4. Run and verify

The pipeline generated by the runner configuration commit will wait until a matching runner is online. Once online, return to **Build → Pipelines** and retry the pending pipeline (or run a new pipeline on `main`).

A real success requires:
1. `unity_project_validate` passes.
2. `unity_build_linux` reports `OMNIS UNITY BUILD SUCCEEDED`.
3. The job publishes `UnityProject/Builds/Linux/Omnis.x86_64` and its accompanying runtime files as artifacts.
4. The executable is launched and play-tested separately before calling the game playable.

## Why this avoids the quota block

GitLab-hosted instance runners consume included compute minutes. The custom runner uses the project's own machine and its Docker engine, so the runner compute is not billed as GitLab-hosted instance-runner time. It still consumes the machine's CPU, memory, disk, and network. See the [GitLab compute-minutes documentation](https://docs.gitlab.com/ci/pipelines/compute_minutes/) and [Docker executor documentation](https://docs.gitlab.com/runner/executors/docker/).


## 5. Optional native Windows release runner

The Linux runner produces the Linux player only. For a native Windows build, register a separate protected project runner on a Windows machine in the project Settings → CI/CD → Runners.

Configure:
- Description and exact tag: omnis-windows
- Run untagged jobs: off
- Protected: on
- Executor: shell, using PowerShell
- Install Unity Editor 6000.3.0f1 including Windows Build Support
- Register the runner and wait until it shows Online

Set the protected CI/CD variable UNITY_LICENSE to type File containing the actual valid Unity .ulf licence file. Do not commit the licence. If Unity is installed somewhere other than the default, set the protected variable UNITY_EDITOR_PATH to the full Unity.exe path.

When the runner is online, run the manual unity_build_windows job in the main branch pipeline. It should produce UnityProject/Builds/Windows/Omnis.exe and a release manifest. A job waiting for the runner is not a successful build.
